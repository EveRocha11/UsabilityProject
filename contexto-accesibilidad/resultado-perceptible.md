Principios
• Cada principio incluye pautas, criterios de éxito, técnicas suficientes, técnicas recomendables y fallos.
• Las pautas en sí no son comprobables.
• Los criterios de éxito son comprobables. También los criterios de éxito son tecnológicamente neutros.
• Las referencias específicas a la tecnología se encuentran en las técnicas suficientes (para remover
barreras en general) y recomendables (para remover barreras para grupos específicos).
• Los fallos son técnicas que si se utilizan pueden introducir barreras de accesibilidad.

Principio Perceptible

Perceptibilidad
• La información y los componentes de la interfaz de usuario
deben ser presentados a los usuarios de manera que puedan
percibirlos.

Perceptibilidad
• El contenido puede no ser perceptible si los autores de la web:
• Utilizas fuentes de letra pequeñas o difíciles de leer.
• Especifican colores para las fuentes de letras que no ofrecen suficiente contraste con
el fondo.
• Omiten la descripción textual de una fotografía o imagen.
• No proporcionan subtítulos o una transcripción de los contenidos multimedia y de
audio.
• Exigen respuestas cronometradas (con límite de tiempo).
• Estos tipos de barreras de percepción se abordan en las pautas 1.1, 1.2 y
1.4.

Pauta 1.1. Texto alternativo
1.1. Alternativas de texto para cualquier contenido que no sea de texto

Contenido no textual
• Todos los contenidos no textuales que se presentan al usuario deben
tener una alternativa textual que cumple una función equivalente.
• Excepciones: controles, entradas, pruebas, experiencias sensoriales,
CAPTCHA, decoraciones.

El arte del texto alternativo
• Una de las formas más comunes de eliminar las barreras asociadas a
los contenidos visuales es utilizar el atributo HTML alt de la etiqueta
img. Sin embargo, crear un texto alternativo eficaz es todo un arte. El
| texto | alternativo | debe | tener | 125 | caracteres |     | o menos. |
| ----- | ----------- | ---- | ----- | --- | ---------- | --- | -------- |
• El texto alternativo ayuda a las personas que tienen dificultades para
percibir contenidos visuales, entender el significado de fotografías,
dibujos y otras imágenes, comprender información sonora y a las
| personas | sordociegas |     | que pueden |     | leer | el texto | en braille. |
| -------- | ----------- | --- | ---------- | --- | ---- | -------- | ----------- |
• Además ayuda a usuarios con navegadores textuales, conexiones
lentas a Internet o planes de datos limitados. También permite buscar
| imágenes | en la | Web. |     |     |     |     |     |
| -------- | ----- | ---- | --- | --- | --- | --- | --- |

Pauta 1.3 Adaptable
• Las personas deben ser capaces de comprender los contenidos web. La
capacidad de comprender contenidos web puede verse afectada por la
estructura, las relaciones entre elementos, su complejidad o la coherencia
en la presentación.
• Las barreras perceptivas de este tipo se producen cuando:
• La información está mal estructurada.
• La navegación o la presentación son incoherentes.
• La ordenación de los contenidos es ilógica.
• Los elementos funcionales no se describen o etiquetan eficazmente.
• El contenido sólo funciona en una única orientación de visualización; o
• Las instrucciones hacen referencia al contenido únicamente a través de la forma, el
color, el tamaño o la ubicación visual.
• Este tipo de barreras perceptivas se abordan en el Criterio de Éxito 1.3.3

Conclusiones
• Aplicar el principio Perceptible asegura que el contenido no dependa
de un solo sentido, como la vista o el oído. Gracias a alternativas
como texto alternativo, subtítulos o transcripciones, las personas con
discapacidad visual o auditiva pueden acceder a la información en
igualdad de condiciones.
• El principio Perceptible promueve que los contenidos sean visibles,
audibles y comprensibles para el mayor número posible de usuarios,
independientemente de sus capacidades o del dispositivo que
utilicen, reduciendo así las barreras de acceso a la web.
